# 输入框润色与模板

在发送之前把输入框里的草稿润色一遍，并把精选模板插到光标处。

## 设置卡上改的是什么

这张卡是两个列表编辑器，不是一堆开关。

- **角色库** — 每行是名称、表情、分组、说明与正文，输入框的「模板」选择器读的就是这张表。把表清空不是关掉功能：插件会改用随包内置的精选集合，需要时由宿主现取，而不是把整份塞进表单描述里。
- **允许导入的目录** — 额外允许导入角色文件的绝对目录。留空不额外放行：这张卡没有会话上下文，因此只剩随包内置的 `agents/` 角色库可导入；带会话调用的端点还接受该会话 cwd 之内的路径。这些区域之外的绝对路径仍被拒绝，而不是等着填的占位。

两者都是每次请求现读，改完下一次动作就生效，不需要重启宿主。

## 卡上没有的值

`organizeTimeoutMs` 虽标为即时生效，但卡上没有它的旋钮：客户端只读它来对齐自己的 fetch 超时，真正先超时的是宿主那侧。

`maxSnippetBytes` 与 `readConcurrency` 是刻意留在卡外的部署假定值。写在本插件注册行的 `config:` 块，改值随重启生效。

## 需要外部提供什么

不需要外部 CLI、解释器或自有凭据。它用宿主的模型运行时与模型选择（会话活 Agent 的当前选择，取不到时回落默认选择）、会话存储与文件系统服务；润色跟随当前会话选定的模型，所以在输入区换模型会改变下一次润色用的是哪个。
